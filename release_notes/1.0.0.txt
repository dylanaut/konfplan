- Migrate database layer from PostgreSQL to SQL Server (Azure SQL Edge)
  * Migrate database layer from PostgreSQL to SQL Server (Azure SQL Edge)
  Swaps the persistence stack to Microsoft SQL Server, using
  mcr.microsoft.com/azure-sql-edge as the local dev/prod-test container
  image since it's the only SQL-Server-compatible image that runs
  natively on ARM64 (Apple Silicon); mcr.microsoft.com/mssql/server
  requires amd64 emulation. Azure SQL Edge was officially retired by
  Microsoft on 2025-09-30 (no further updates) but remains pullable
  and is the only practical local ARM64 option today.
  - verfuegbareSlotIds (previously a native Postgres bigint array with
    no SQL Server equivalent) is now a proper @ElementCollection with
    a composite @AssociationOverride per NutzerVerfuegbarkeit/
    RaumVerfuegbarkeit/VortragVerfuegbarkeit, each backed by its own
    join table. No caller changes needed anywhere in the codebase.
  - pom.xml: quarkus-jdbc-postgresql -> quarkus-jdbc-mssql,
    flyway-database-postgresql -> flyway-sqlserver.
  - application.properties: db-kind=mssql, SQL Server JDBC URL syntax,
    devservices pinned to the azure-sql-edge image, EULA acceptance
    via container-license-acceptance.txt.
  - V1__schema.sql/V2__data.sql/import-dev.sql rewritten for T-SQL
    (bit, datetime2, varchar(max) for the old Postgres oid/jsonb LOB
    columns, NEXT VALUE FOR, TRUE/FALSE -> 1/0), derived from the DDL
    Hibernate itself generates against a real azure-sql-edge instance
    rather than guessed, plus hand-added FKs from the new slot join
    tables to Slot(id).
  - docker-compose.yml, ensure_prod_db.sh, ensure_prod_infra.sh,
    kill_dev_container.sh switched to Azure SQL Edge. sqlcmd is not
    bundled in this image; healthchecks and the one-off "CREATE
    DATABASE konfplan" step use isql (unixODBC), which is. Removed
    init_db.sh/init_roles.sh (Postgres-specific, confirmed unused).
  Verified end-to-end: full H2 test suite (115/115), a real
  quarkus:dev run against azure-sql-edge, a real Flyway migration
  from an empty database (the actual %prod code path, not just
  Hibernate drop-and-create), CSV seed data landing correctly in the
  new join tables, LOB/JSON round-tripping on Planungsergebnis, German
  umlaut preservation, and the docker-compose stack including the
  idempotent CREATE DATABASE step.
  * Fix ReferentDashboard profile not loading and save 409
  - GET /api/referenten/profile and GET /api/referenten/veranstaltungen
    both threw LazyInitializationException accessing Nutzer.veranstaltungen
    outside a Hibernate session - neither endpoint had @Transactional.
    The frontend only logged the failure, leaving the profile at its
    default (versionless) state, so the subsequent PUT always sent a
    missing version and got rejected with 409 (optimistic lock).
  - The Biografie textarea was bound to referent.bio while the backend
    DTO field is biography, so it would have stayed empty even after
    the 500 fix.
  Verified against the running dev backend: both GET endpoints return
  200 with full data, PUT now succeeds and correctly bumps the version,
  and a full browser run through login -> profile -> save shows no
  errors.
  * Introduce loginName as the immutable identity key; email becomes optional
  Nutzer previously used email as login credential, unique business key,
  and contact address all at once. Adds a new loginName field that takes
  over the first two roles - immutable once assigned, unique, required -
  while email stays as an optional contact-only field.
  Backend:
  - Nutzer.loginName: NaturalId, no setter (assignLoginName() enforces
    write-once), backed by a plain unique index; email keeps its existing
    nullable filtered-unique-index mapping unchanged.
  - Login, JWT (upn/sub), forgot-password, and every "resolve the current
    user from the JWT" call site (Referent/Teilnehmer/Prioritaeten/Report/
    Kalender resources, VeranstaltungService's organizer resolution) now
    key off loginName instead of email.
  - Mail-sending guarded on email presence everywhere it wasn't already
    (MailService.sendVortragsRegistrierung/sendVerfuegbarkeitChanged
    Notification, forgotPassword, senderEmail fallback to app.mail.admin).
  - Fixed two real bugs surfaced by making email routinely null:
    AdminService.updateUser NPE'd comparing old/new email with .equals()
    instead of Objects.equals(), and createUser skipped password-hash
    generation for no-email users.
  - CSV import (Admin/Teilnehmer/Referent/Vortrag/Veranstaltung/
    Verfuegbarkeiten/Prioritaeten) now keys off a LoginName column;
    email import stays optional. All 5 fixture datasets regenerated with
    loginName derived from each email's local part, and cross-reference
    columns (Referent_Email, Organisatoren_Emails, etc.) rewritten to
    reference loginName instead.
  Frontend:
  - Login form is loginName-based; forgot-password copy reflects that a
    user without an email can only get a password reset from an Admin.
  - UserEditorModal has a required loginName field, editable only when
    creating a new user (disabled thereafter, mirroring the existing
    role-select pattern). Admin tables and both self-service dashboards
    show loginName, with email demoted to an optional secondary field.
  Verified: full backend test suite (115/115) after updating ~16 test
  files affected by the new NOT NULL constraint, plus a live end-to-end
  pass against the running SQL Server dev container - login by loginName
  succeeds and by email fails, JWT claims carry loginName, forgot-password
  sends mail only when email exists while still returning an identical
  202 for unknown users, and a real CSV import via REST creates a user
  with the new LoginName column correctly populated.
  * rename vortragsmanager to konfplan in docker images
  * Serialize Berufsfeld via its German display name, not the enum constant
  Round-trips Vortrag.berufsfeld through @JsonValue/@JsonCreator on the
  Berufsfeld enum so the API always shows/accepts the human-readable name
  instead of the Java constant identifier. Drops the frontend's duplicated
  constant/label mapping in favor of using the display names directly.
  * Add sortable Gruppen column to the Prioritäten-Matrix table
  The Verfügbarkeits-Matrix table already showed a sortable group column
  next to the participant name; the Prioritäten-Matrix table above it was
  missing the same column despite sharing the same sort state.
  * Report solver timeout instead of leaving the Planerstellung button stuck
  MiniZinc prints "=====UNKNOWN=====" when its --time-limit expires without
  finding a solution, but this was never checked, so the run silently
  returned an empty result with a generic "keine Lösung"-message. The UI's
  status polling also ignored lastError entirely, so users got no feedback
  and the button state resolved without any explanation.
  Now the timeout case throws a dedicated MinizincException naming the
  configured limit, and the frontend surfaces that message to the user
  instead of silently switching to the Ergebnisse tab.
  * hashed default password for import in dev or test mode
  * Add live countdown to the Planerstellung cancel button
  Shows the remaining seconds of the configured solver timeout on the
  "Erstellung abbrechen" button while a plan is being generated, so the
  admin can see how long the current run is expected to keep going.
  * Stop wrapping dev-data seeding in one giant transaction
  DevDataInitService.onStart() was @Transactional, so the whole CSV-based
  seeding loop for every configured dataset shared one JDBC connection.
  Row-by-row imports across multiple datasets routinely exceeded even the
  already-bumped 3-minute dev transaction timeout; once Narayana's reaper
  rolled the transaction back mid-loop, every subsequent statement failed
  with "Could not prepare statement [Connection is closed]".
  Each importXFromCsv step is already independently @Transactional, so
  removing the outer annotation lets every step commit on its own instead
  of sharing one long-lived, timeout-prone transaction.
  * Don't hold a DB transaction open across the MiniZinc solver call
  erstellePlan() was @Transactional end-to-end, so the transaction spanned
  the whole MiniZinc invocation, which blocks for up to the admin-configured
  solver timeout (now surfaced and encouraged via the PlanungTab countdown).
  Once a run took longer than the JTA transaction timeout, Narayana's reaper
  rolled the transaction back while the app thread was still waiting on the
  external process; persisting the result afterwards then failed with
  "ARJUNA016102: The transaction is not active!".
  Split the DB work into two short, independently-transactional steps
  (bereiteDznVor and speicherePlanungsergebnis) with the long-running,
  non-transactional MiniZinc call in between. speicherePlanungsergebnis now
  re-fetches the Veranstaltung by id instead of reusing a reference that may
  be stale after a multi-minute solver run. As a side effect, a collision
  detected in this async safety-net check now also surfaces via lastError
  instead of being silently swallowed.
  * Rework Planqualität scoring: separate Güte and Raumwechsel-Anzahl
  Replace the single "kosten" score with an explicit "guete" objective
  and a standalone "raumwechsel" count (previously baked into the
  solver's cost as an implicit penalty), and remove the unused MiniZinc
  output-only oid parameters that broke solving. Fix result persistence
  using valueToTree instead of putPOJO so Jackson can deserialize the
  oid arrays as long[]. Display the resulting PlanQualitaetDto fields in
  the Ergebnisse tab, which previously received but never rendered them.
  * Cancel in-flight requests and running Planerstellung on logout; tune PlanErstellungService logging
  Logout previously only cleared client-side auth state, leaving any
  running MiniZinc solve and the Ergebnisse-tab status polling active.
  auth.js now sends DELETE /api/planungen (best-effort, admin-only)
  before clearing the token, and axios.js tracks every request via an
  AbortController so cancelAllRequests() can abort whatever is still
  in flight. AdminDashboard.vue also clears its polling interval on
  unmount, which previously kept firing after navigating away.
  Also tightens PlanErstellungService/AuffuellungService logging
  (debug-gate the full dzn dump, add start/progress markers) picked up
  from IDE edits.
  * Disable Planerstellung cancel button outside the actual MiniZinc solve
  The configurable timeout in PlanungTab.vue only bounds the MiniZinc
  solve itself, not the DB-heavy dzn-preparation and result-persistence
  steps around it - and cancel() can't interrupt those since they hold
  no live process handle. Track the current step as a Phase enum
  (VORBEREITUNG/BERECHNUNG/PERSISTIERUNG) in PlanErstellungService,
  expose it via GET /api/planungen/status, and only enable the
  Abbrechen button while phase is BERECHNUNG; otherwise show a disabled
  placeholder. The countdown in PlanungTab.vue now also starts when
  BERECHNUNG begins rather than at the initial click, since it
  previously ran down during preparation before solving even started.
  * Retry login up to 3x on transient failures right after app start
  The very first login attempt right after 'mvnw quarkus:dev' starts can
  occasionally fail with a real 401 (not just a connection error) even
  with correct credentials, showing "Login fehlgeschlagen" - the prior
  retry only covered plain connection failures and only retried once.
  Root cause of the transient 401 couldn't be pinned down exactly, so
  harden the retry instead: 3 attempts with a short delay for any
  failure (network or HTTP), covering the startup race either way while
  still failing fast on a real wrong-password attempt (after the same
  3 retries).
  * Fix Prioritaeten report cell/slot data and report layout
  PrioReport never exposed wvOids/slotOids/raumOids, so getSlotInfo()
  in Prioritaeten.vue always resolved to undefined values. SlotDto's
  tag()/start()/ende()/zeitraum()/zeitraumTag() also silently never
  serialized to JSON since Jackson only auto-detects getXxx()-style
  methods, breaking date/time display across Prioritaeten, Stundenplan
  and TeilnehmerZuordnungen.
  Also open the six ErgebnisseTab report links in a new browser tab,
  and stretch the three Stundenplan-Übersicht cards to the full row
  width (col-md-3 -> col-md-4).
  * Fix N+1 priorities query and cache parsed MinizincResult
  Every report request recomputed the full DashboardData from scratch,
  including 3xN individual DB round-trips (one per Teilnehmer, called
  three times) to load Wahlvortrag-Prioritaeten. Bulk-load them once per
  Veranstaltung instead via PrioritaetService.getVortragPrioritaetenByVeranstaltung().
  Also cache the MinizincResult parsed from Planungsergebnis's JSON blob,
  keyed by its id/version, so repeated report views don't re-parse the
  same (potentially large) besucht/instanz_slot/instanz_raum arrays on
  every request. A new plan bumps the @Version and invalidates the cache.
  * Build DashboardData only for the report actually requested
  getDashboardData() unconditionally computed every derived structure
  (Belegungsdetails, Teilnehmer-Erfuellung, Teilnehmer-Stundenplan,
  Planungsstatistik, WahlErfuellungStats) on every single report
  request, even though each of the three report endpoints only ever
  consumed one of stundenplan/teilnehmerReport/prioReport.
  Split it into getStundenplan()/getTeilnehmerReport()/getPrioReport(),
  each building the shared base data once and then running only the
  computation steps its own report actually needs.
  * Fix N+1 queries in Planerstellung's data preparation phase
  appendTnPrios ran one Prioritaet.find() per (Teilnehmer x Wahlvortrag)
  pair - for realistic event sizes that's thousands of individual DB
  round-trips just to build the priorities matrix for MiniZinc. Reuse
  PrioritaetService.getVortragPrioritaetenByVeranstaltung() (already
  introduced for the report N+1 fix) to bulk-load it once instead.
  pruefeKollisionen, which runs on every Planerstellung attempt, had the
  same shape: one NutzerVerfuegbarkeit.findById() per Teilnehmer, one
  RaumVerfuegbarkeit.findById() and another NutzerVerfuegbarkeit lookup
  per Pflichtvortrag, plus a Slot.findById() per slot id inside the rare
  collision-message branch. Bulk-load all three into maps up front.
  * experiment mit drop of exists Fehler durch SqlDialect gescheitert

- Remove redundant id field shadowing AbstractIdDto.id
  VortragDto and ReferentVeranstaltungDto each redeclared "public Long
  id", shadowing the field already inherited from AbstractIdDto (via
  AbstractVersionedDto). Flagged by SpotBugs as MF_CLASS_MASKS_FIELD

- Invalidate outstanding JWTs on password reset
  * Invalidate outstanding JWTs on password reset (#63)
  Resetting a password (self-service AuthResource#resetPassword, or the
  admin rescue path AdminService#resetPassword added in #60) only changed
  the stored hash - it left any already-issued JWTs for that user untouched.
  If an account was compromised and an attacker already holds a valid token,
  resetting the password wouldn't lock them out until the token's natural
  4h expiry.
  Adds TokenInvalidationService: an in-memory per-loginName "invalid before"
  timestamp, in the same single-instance-friendly spirit as the existing
  LoginRateLimiterService/ForgotPasswordRateLimiterService (accepting that a
  restart clears it, given the short 4h token lifetime). Enforcement happens
  via TokenInvalidationAugmentor, a SecurityIdentityAugmentor that runs on
  every authenticated request and compares the JWT's iat claim against that
  threshold - the idiomatic Quarkus mechanism for rejecting otherwise

- Fix bootstrap.sh secret permissions to survive non-root containers
  Secrets were generated with chmod 600, readable only by the host user
  that ran bootstrap.sh. Docker Compose file-secrets bind-mount them
  with the host file's permissions intact, but the app/keycloak images
  run as a non-root user (e.g. USER 185 in Dockerfile.jvm), so the
  container got "Permission denied" reading them - observed as the app
  crash-looping on "grant type 'client_credentials' requires client
  secret" and, from the browser, a redirect loop against a dead
  upstream. Switch to chmod 644 (the secrets/ directory itself stays
  chmod 700, and secrets are still read-only-mounted into containers).
  Update Deployment-DockerCompose.adoc accordingly and add a
  troubleshooting entry plus manual fix-up command to
  Ubuntu-Frischinstallation.adoc for already-generated secrets.
