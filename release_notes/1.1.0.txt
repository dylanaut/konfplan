- Fix production crash from writing to a read-only import.meta.env property
  Vite statisch-ersetzt import.meta.env.VITE_API_URL beim Production-Build
  (auch als Zuweisungsziel), wodurch aus der Zeile effektiv
  "undefined = undefined;" wird - das wirft im Strict Mode einen TypeError,
  weil "undefined" eine read-only globale Property von window ist. Der
  baseURL-Fallback war zudem fuer echte Deployments (Quinoa, gleicher
  Origin) falsch und zeigt jetzt korrekt auf eine relative URL.

- Export/Import von Planungsdaten für externe MiniZinc-Berechnung

  eine Veranstaltung herunterzuladen, extern mit der minizinc-CLI zu berechnen
  und das Ergebnis anschließend wieder als Planungsergebnis zu importieren.

- Referenten-Verfügbarkeit: 403 beim Ändern von Slots beheben
  * Checkbox "mehrfach halten" im ReferentDashboard ausblenden
  Das wiederholbar-Feld wird derzeit noch nicht ausgewertet, daher Checkbox
  samt Frame vorerst unsichtbar schalten statt aus dem Datenmodell zu entfernen.
  * Referenten-Verfügbarkeit: 403/500 beim Ändern von Slots beheben
  Zwei Bugs im Zusammenspiel:
  - Frontend schickte {userId, slotId, isAvailable} statt des vom Backend
    erwarteten {nutzerId, veranstaltungId, verfuegbareSlotIds}, wodurch
    dto.nutzerId immer null war -> 403.
  - Backend rief anschließend clear()/addAll() auf dem von
    getVerfuegbareSlotIds() zurückgegebenen unveränderlichen Set auf, was
    mit UnsupportedOperationException (500) fehlschlug. Jetzt wie in
    TeilnehmerService.updateVerfuegbarkeit über setVerfuegbareSlotIds(...).
  * Frontend an Verfügbarkeits-API-Vertrag anpassen (nutzerId/verfuegbareSlotIds)
  Payload und Response-Parsing für den Verfügbarkeits-Endpoint waren auf
  ein veraltetes Contract-Format ausgelegt, das nicht mehr zum Backend-DTO
  passt (siehe vorherigen Commit). Frontend jetzt analog zu
  TeilnehmerDashboard.vue: volle Slot-Id-Menge lokal togglen und komplett
  ersetzen statt Einzel-Slot-Toggle zu senden.
  * Regressionstest für #143: Referent kann Verfügbarkeit aktualisieren
  Deckt POST /api/referenten/veranstaltungen/{vid}/verfuegbarkeiten end-to-end
  ab und stellt sicher, dass der korrekte Contract (nutzerId/veranstaltungId/
  verfuegbareSlotIds) akzeptiert wird und die Slot-Ids tatsächlich persistiert
  werden.

  mit Speichern/Abbrechen ersetzt die inline immer sichtbare Vortragsdetails-Sektion
  im ReferentDashboard. Der globale "Alles speichern"-Button entfällt; stattdessen
  bekommt nur das Profil-Formular einen lokalen Speichern-Button, der ausschließlich
  bei ungespeicherten Änderungen (dirty state) erscheint - die übrigen Sections
  (Verfügbarkeit, Veranstaltungsanmeldungen) speichern bereits pro Klick sofort.
  version und abschluss werden im Modal ohne eigenes UI-Feld durchgereicht, da das
  Backend sie beim Update sonst stillschweigend auf null zurücksetzen bzw. das
  optimistische Locking mit einem falschen Konflikt fehlschlagen lassen würde.
  Die Checkbox "mehrfach halten" bleibt wie im Original vorerst ausgeblendet
  (v-if="false"), da das Feature backendseitig noch nicht ausgewertet wird.
